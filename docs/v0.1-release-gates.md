# v0.1 release gates

This file is the short operational view of the current delivery scope. Normative details remain in
`specs/07-implementation-plan.md`.

| Gate | Outcome                                                              | Current state    |            Paid solver envelope |
| ---- | -------------------------------------------------------------------- | ---------------- | ------------------------------: |
| 0–4  | Loader, candidate SDK, Harbor ACP, durable controller, real proposer | accepted         |        historical evidence only |
| 5    | one productized iteration CLI                                        | accepted         | one preflight smoke if required |
| 6    | real K=3 multi-generation crash/resume proof                         | accepted         |                 9 solver trials |
| 7    | installable open-source v0.1 release candidate                       | accepted         |          reuses Gate 6 evidence |
| 8    | continuous Terminal-Bench improvement profiles                       | optional/not run |           separately authorized |

## Gate 5 — Productized iteration closure

Accept only when one documented command connects the real proposer, candidate builder, Cordis Loader, Harbor
evaluator, normalizer, durable controller and Archive. `init/run/resume/status/audit/doctor` must share a versioned
config and fail before a paid launch when prerequisites or budget are unavailable.

## Gate 6 — Stable iteration proof

Run up to 12 observed baseline tasks in frozen batches to discover a real failure. Freeze the failure pool, produce
three unique candidates across at least two lineage depths, and evaluate each on one preselected failed-baseline
task. Inject one crash after an external effect and prove exactly-once recovery. Score improvement is not required.

Gate 6 passes as `STABLE_ITERATION_VERIFIED`. If all 12 baseline tasks pass, stop as `NO_REAL_FAILURE_SIGNAL`.

## Gate 7 — Open-source release

Accept only after a clean-machine install, real Loader plus Gate 6 smoke, complete public documentation and
governance files, SBOM/provenance/checksums/leak scan, full tests, and tested uninstall/rollback/backup restore.
The release status is `OPEN_SOURCE_V0_1_RELEASE_CANDIDATE`, not a benchmark claim.

Gate 5–7 acceptance evidence is recorded in
[`audits/2026-08-14-v0.1-release-candidate.md`](audits/2026-08-14-v0.1-release-candidate.md).

## Gate 8 — Optional continuous improvement

K=10 pilot, K=80 search, one-shot sealed confirmation and official 89×≥5 evaluation are independent post-release
profiles. They use fresh run lineages and do not change whether the v0.1 iteration engine is usable.

## Claim boundary

`STABLE_ITERATION_VERIFIED` means the engine can repeatedly generate, build, evaluate, persist and recover. It does
not mean a candidate improved Terminal-Bench, passed sealed confirmation, reached a leaderboard or achieved SOTA.
