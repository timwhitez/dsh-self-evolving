## Paid release regression

All three credential-gated cases were executed against the official endpoint:

1. the networkless proposer plus trusted Responses gateway produced an admitted child;
2. the real Cordis model composition produced a nontrivial schema-valid proposal;
3. the v0.1.1 multi-file proposer produced an admitted child whose solve replay changed while propose replay stayed
   fixed. The accepted successor took 314.611 seconds for the real-model portion and the file completed 3/3 tests.

The third case exposed two fail-closed defects before its accepted successor. First, the target/preserved mode
contract was evaluated after generation but was absent from the durable proposer request. Second, candidate-owned
Vitest tests ran during proposal authoring while the trusted admission import policy ran only afterward. The repair
binds and validates the mode contract in the request/prompt, gates runtime effects by `config.mode`, and executes the
same candidate import policy plus candidate tests in both `validate_child` and `finish_proposal`. The proposal
sandbox remains networkless and receives neither the API credential nor host environment.
